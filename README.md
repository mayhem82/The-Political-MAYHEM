# The Political MAYHEM

Status: **EXPANDING — VERIFIED SNAPSHOTS ONLY**

The Political MAYHEM is a continuously expanding political tipping intelligence system. It is designed to ingest contemporaneous political evidence, preserve what was knowable at each point in time, issue and version forward projections, reconcile outcomes, analyse failures, map relationships across an expanding multidimensional evidence space, and later use retroactive ingestion to discover signals that can improve future projections without rewriting prior decisions.

The system is nonpartisan. Its purpose is descriptive intelligence, forecasting, provenance, calibration, failure analysis and relationship discovery — not political persuasion, campaign targeting or voter manipulation.

## Core operating model

**INGEST → ANALYSE → MAP RELATIONSHIPS → PROJECT → PRESERVE → RECONCILE → LEARN → RE-INGEST EXPANDED STATE → ANALYSE AGAIN**

The system has no terminal completion state. Each current state is a reproducible snapshot of an expanding intelligence system.

## Build order

The forward/live tipping system is built first. It must establish a genuine contemporaneous baseline before any large retroactive discovery layer is introduced.

1. Build forward ingestion and evidence provenance.
2. Build political event/state lifecycle handling.
3. Build projection capture and immutable version history.
4. Build result/outcome reconciliation and grading.
5. Build failure retention and analysis.
6. Build continuously expanding relationship mapping.
7. Allow a genuine forward baseline to accumulate.
8. Only then add retroactive ingestion and retrospective analysis.
9. Retro-derived discoveries may append better current projections from the moment they are discovered forward, but may never rewrite earlier projections or pretend the system knew them earlier.

## Temporal integrity

Every evidence item must preserve when it became knowable, where it came from, when it was captured, and what projection versions could legitimately use it.

A prior projection is immutable. A later projection may differ because of new live evidence or a newly discovered retro-derived relationship, but it must be stored as a new version with explicit lineage.

Example:

- `P0` — original contemporaneous projection.
- `P1` — revised after new live evidence.
- `P2` — revised after a retro-derived relationship becomes available to the forward system.
- `P3+` — subsequent evidence-driven revisions.

Retroactive analysis can improve the present. It cannot alter the past.

## Signal objective

The system is intended to discover signals that matter, including signals that alter the psychological conditions of political actors.

A politically important signal may change what an actor believes is possible, costly, safe, urgent, legitimate or inevitable. The system should therefore distinguish:

- the originating observable signal;
- the observable behavioural response;
- the inferred psychological condition;
- downstream responses by other actors;
- resulting changes in the political environment;
- eventual outcome effects, if any.

Psychological state is inferential unless supported by direct evidence. Observable behaviour and stated reasoning must be preserved separately from interpretation.

## Relationship discovery

The system must not decide in advance which signals matter. It continuously tests and maps relationships across political dimensions such as time, electorate, candidate, party, polling, preference flows, incumbency, geography, campaign activity, media attention, funding, endorsements, issue salience, historical swing, turnout, redistribution, candidate changes, institutional behaviour, source reliability and actor-response dynamics.

Signals may be stable, unstable, conditional, threshold-dependent, interaction-dependent, actor-specific, geography-specific, election-specific, regime-specific, proxies for deeper mechanisms, or noise. Failed signals remain evidence.

## Public repository / intelligence boundary

The repository may be publicly accessible, but repository visibility does not mean all operational intelligence must be published. Public architecture and deliberately published outputs should remain separable from unreleased analysis, provisional signals, internal source-performance judgments, unresolved hypotheses and private working state.

The system should default to explicit provenance and exposure classification when operational intelligence begins to be persisted.
